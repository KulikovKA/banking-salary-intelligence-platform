# Уровни reasoning для GPT-6 Luna

Назначения — инженерная рекомендация для этого проекта, не результат замера производительности модели на его коде. Дата: 09.10.2026. Они относятся к модели-исполнителю разработки, а не к будущему LLM API банковского ассистента.

В плане используются названия пользователя: **Light, Medium, High, Extra High**. Для конфигурации API: Light соответствует `low`, Medium — `medium`, High — `high`, Extra High — `xhigh`. Light — условное название в этом плане, а не отдельное API-значение. Поддержка low/medium/high/xhigh проверена по [официальной странице GPT-6 Luna](https://developers.openai.com/api/docs/models/gpt-6-luna). `none` и `max` вне запрошенного диапазона. Отображение названий в конкретном интерфейсе может отличаться.

| Уровень | Где применять | Где не применять |
|---|---|---|
| Light / low | Только перенос уже проверенных результатов в отчёт, статусы, ссылки, форматирование документации | Выбор архитектуры, код тарифов, auth, миграции, оценка корректности результатов |
| Medium | Окружение по спецификации, UI по готовым контрактам, фиксированные метрики | Неоднозначная domain logic, сложные гонки и безопасность |
| High | Основной рабочий режим: парсеры, интеграции, полный API, auth, эксплуатация и evaluation | Не снижать до Medium при непонятной ошибке только ради скорости |
| Extra High / xhigh | Целостность архива, retries/leases, даты/условия/публикации, сравнения, budgets, adversarial security, сложные исправления | Не нужен для каждого изменения текста, обычной формы или обновления статуса |

## Как выполнять объединённый блок

1. Перед запуском выбрать уровень блока. Текст prompt сам по себе не переключает настройку модели; уровень задаётся в интерфейсе/конфигурации запуска.
2. Выполнять внутренние этапы по порядку, проверять их AC и сохранять checkpoints. Один WORK — одно поручение, но не требование уложить всю работу в один ответ или один commit.
3. Для WORK-08 уровень High, но AI-002 выполнять на Extra High. Для WORK-13 базовый Medium, UI-003 и UI-006 — High. Если переключать режим неудобно, выбрать максимальный требуемый уровень на весь этот WORK.
4. Если диагностика упирается в противоречивые даты, потерю evidence, race, ACL bypass, утечку или неоднозначный расчёт — повысить до Extra High, сформулировать reproducer. Не повторять без изменений неудачный подход.
5. После завершения проверок можно отдельным коротким проходом Light оформить готовые результаты/статусы. Такой проход не выполняет новую приёмку и не ставит DONE без готовых доказательств.
6. Любые изменения архитектурных контрактов требуют ADR по действующим правилам; высокий reasoning не даёт права игнорировать gate, выбор пользователя или отсутствие источника.

Нет целого инженерного WORK-блока с уровнем Light: каждый включает проверки или решения, для которых минимум Medium. Light указан явно как режим административного завершения каждого Luna-блока. Независимые WORK-20 и WORK-22 оставлены Astra; режим Luna для них неприменим.
