# Проверка пакета проектирования

Дата: 09.10.2026. Объект проверки: документация proposed v1.1, а не приложение. Это проверка согласованности текущего пакета, не будущий независимый production audit.

## Выполнено

- Прочитан весь текстовый запрос пользователя, рассмотрены три растровые схемы Miro A/B/C.
- Проверена исходная рабочая папка: кода/конфигураций приложения не было; внешний Git root не изменялся.
- Программно проверены 62 уникальных task IDs, 62 ТЗ и 62 prompts; всего 248 подзадач с локальными ID.
- Все технические dependencies указывают на существующие задачи; граф ацикличен; EXECUTION_ORDER топологически корректен.
- Все задачи имеют TODO и размер S/M/L, задач XL нет.
- Проверены все Markdown локальные ссылки, упоминаемые task IDs, парность code fences и JSON parse TASK_INDEX. Ошибок не найдено.
- Проверено отсутствие файлов приложения/скриптов: только Markdown и JSON документации. Временный генератор документов удалён.
- Сверены POC/MVP границы, provider gate, ownership, immutable evidence, unknown semantics и миграционный порядок.

Инвентарь после добавления этого отчёта: 157 Markdown-файлов и 1 JSON-индекс. Число файлов не является показателем готовности приложения.

## Исправления при проверке

1. В DB-003 не должно быть FK на ещё не созданную users: nullable reviewer/actor UUID для local POC, FK и production Principal validation вводит DB-004.
2. SRCH-001 добавляет индекс после facts schema, до auth: порядок Alembic определяется фактическим down_revision, а не цифрой в имени файла.
3. POC comparison result не выдаётся за сохранённый personal comparison_run до появления DB-004; ограничение описано в POC_SCOPE.
4. Required limitations формирует backend, LLM не вправе скрыть невыгодную сторону сравнения.
5. Неизвестное потребление provider после crash остаётся консервативно зарезервированным, чтобы retry не обошёл budget.

## Не выполнялось и не заявляется

Запуск приложения, unit/integration/E2E/security/load тесты, real provider integration, многодневные source probes, создание реального tariff corpus, deployment, backup restore и финальный независимый аудит. Это будущие задачи, а не выполненные проверки. Библиографический web research не доказывает стабильность доступа к банковским сайтам и не заменяет правовое решение ответственного.

## Согласование

Перед началом разработки пользователь принимает G0 и предложенные ADR. Источники принимаются по реальным G1 evidence, POC по G2. LLM/provider по-прежнему не выбран. Все открытые продуктовые/правовые/лицензионные решения перечислены в OVERVIEW, RISKS и MASTER_PLAN.
